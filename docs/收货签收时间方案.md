# 企迈收货签收时间获取方案

## 背景

盘点系统中需要判断"订单签收超过多久了"，需要获取门店收货签收时间。

## 数据链路

```
订货单 DH* → 报货单 BH* → 配送单 PS* → 出库单 → 入库单
   ✅           ✅          ⚠️控制台    (无API)   ⚠️控制台
```

## 方案 A（主方案）：报货单 `updatedAt` 近似签收时间

### 接口

```
POST https://openapi.qmai.cn/v3/scm/order/declare/order/detail
权限：9.1.2 报货单详情（已开通）
```

### 逻辑

- `orderStatus = 4`（已完成）时，`updatedAt` 就是门店收货完成时间
- 与内部网关 `receiptAt` 实测仅差 **1 秒**

### 入参

```json
{
  "declareNo": "BH20260730000003"
}
```

### 响应关键字段

| 字段 | 说明 |
|------|------|
| `declareNo` | 报货单号 |
| `orderStatus` | 4=已完成 |
| `updatedAt` | 完成时间（≈签收时间） |
| `declareProductList` | 商品明细（含 productCode/Name/Num/Price） |

### 调用方式

1. 先调 **报货单列表** 获取门店的报货单号：
   ```
   POST /v3/newPattern/scmApiserver/post/declare/order/list
   参数：storeIdList, createdStartAt, createdEndAt, statusList:[3,4]
   返回：declareNo, requireNoList (DH*), orderStatus, updatedAt
   ```
2. 对已完成订单（`orderStatus=4`），直接用列表里的 `updatedAt` 作为签收时间
3. 需要商品明细时再调用详情接口

### 优点
- 开放 API，无需额外权限
- 全自动，无外部依赖
- 精度足够（差 1 秒）

## 方案 B（交叉验证）：控制台入库单 `inboundAt`

### 接口

```
POST https://inapi.qmai.cn/gw/scm/console/inbound/order/list
认证：Cookie（qm_seller_token + ALL_DATA_SELLERID）
```

### 入参

```json
{
  "createdStartAt": "2026-07-01 00:00:00",
  "createdEndAt": "2026-08-12 23:59:59",
  "pageNo": 1,
  "pageSize": 50,
  "warehouseId": "827599547516627429"
}
```

### 响应关键字段

| 字段 | 说明 |
|------|------|
| `inboundNo` | 入库单号 |
| `bizNo` | CG* 采购单号（inboundType=3 时） |
| `inboundAt` | 入库时间（精确签收时间） |
| `inboundType` | 3=采购入库 |
| `warehouseName` | 仓库名称 |
| `inboundProductList` | 入库商品明细 |

### 缺点
- Cookie 过期时间未知，无法自动刷新
- 登录需手机号+短信+阿里滑块验证码

### 建议用途
- 作为方案 A 的交叉验证
- Cookie 过期不影响主流程
