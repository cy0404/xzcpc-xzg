## 二、🟠 高风险问题

### 2.1 NPE 风险：`validateTaskNotSubmitted()` 未检查 task == null

**文件**：[MpZoneServiceImpl.java](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/service/impl/MpZoneServiceImpl.java:275-283)
**文件**：[MpMaterialServiceImpl.java](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/service/impl/MpMaterialServiceImpl.java:227-235)

```java
private void validateTaskNotSubmitted(Integer taskId) {
    Task task = taskMapper.selectById(taskId);
    if ("submitted".equals(task.getStatus())) {  // ← task 为 null 时 NPE
        throw new BusinessException(4032, "任务已提交不可修改");
    }
}
```

当任务被删除或 taskId 不存在时，`task` 为 `null`，`task.getStatus()` 抛出 `NullPointerException`。

**建议**：增加 `if (task == null) throw new BusinessException(4040, "任务不存在");`

### 2.2 手动 JSON 解析器在值含特殊字符时损坏数据

**文件**：[MpTaskServiceImpl.java](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/service/impl/MpTaskServiceImpl.java:447-527)

```java
// parseBreakdown() — 第 463 行
for (String kv : part.replaceAll("[{}\"]", "").split(",")) {
// parseUnitInputs() — 第 518 行
String val = kv[1].trim().replaceAll("\"", "");
```

两个方法使用 `replaceAll` + `split` 手动解析 JSON，在以下场景会出错：
- 单位名称含逗号（如 `"包,袋"`）→ split 错误拆分
- 值中含有 `{`、`}`、`"` → 被全局替换移除
- JSON 嵌套结构 → 完全无法解析

**建议**：使用 Jackson `ObjectMapper` 或 Gson 替换手动解析。

### 2.3 RestTemplate 无超时配置

**文件**：[CacheConfig.java](xzcpc-xzg/common/src/main/java/com/xzcpc/common/config/CacheConfig.java:42-44)

```java
@Bean
public RestTemplate restTemplate() {
    return new RestTemplate();  // 无 connectTimeout / readTimeout
}
```

`StoreServiceImpl` 和 `MaterialServiceImpl` 使用此 `RestTemplate` 调用外部 API。若外部服务挂起，线程将无限期阻塞，耗尽连接池。

**建议**：配置超时（`SimpleClientHttpRequestFactory` 或换用 `HttpComponentsClientHttpRequestFactory`）。

### 2.4 报表 API 全量加载后内存分页，大流量 OOM 风险

**文件**：[InventoryReportController.java](xzcpc-xzg/server/src/main/java/com/xzcpc/controller/InventoryReportController.java:66-133)

```java
List<Task> tasks = taskMapper.selectList(taskW);  // 全量查询
// ... 内存中聚合后 ...
return R.ok(pageResult(all.subList(from, to), total, pageNum, pageSize));  // Java 内存分页
```

数据量大时（数千门店 × 数月任务），全量加载到内存做分页会导致 OOM。相同问题也存在于 `MaterialRuleServiceImpl.page()`、`ExpenseServiceImpl.dashboard()`、`EmployeeServiceImpl.dashboard()`。

**建议**：使用 SQL 聚合（GROUP BY）和 LIMIT 在数据库层面完成计算。

### 2.5 日志查询接口 `/api/logs/*` 被排除在拦截器外，无认证可访问

**文件**：[AdminWebMvcConfig.java](xzcpc-xzg/server/src/main/java/com/xzcpc/config/AdminWebMvcConfig.java:45-46)

```java
.excludePathPatterns("/api/logs/operation", "/api/logs/login");
```

任何人可查看操作日志和登录日志（含用户名、IP、User-Agent）。

**建议**：从 excludePathPatterns 中移除这两个路径，或加回拦截器校验。

### 2.6 CORS `allowedOriginPatterns("*")`

**文件**：[WebConfig.java](xzcpc-xzg/common/src/main/java/com/xzcpc/common/config/WebConfig.java:15-19)

```java
.allowedOriginPatterns("*")    // 任意域名可跨域
.allowedHeaders("*")           // 任意请求头
```

虽有 `allowCredentials(false)` 降低了 cookie 劫持风险，但攻击者仍可构造钓鱼页面利用用户浏览器向 API 发请求。

**建议**：限制为具体的前端域名。

### 2.7 前端 mock 数据在 API 异常时静默回退

**文件**：[ExpenseDashboard.vue](admin/src/views/expense/ExpenseDashboard.vue:97-134)、[ExpenseList.vue](admin/src/views/expense/ExpenseList.vue:127-146) 等多文件

```typescript
try {
  const res = await getExpenseDashboard(params)
  // ...
} catch {
  // API not yet online, use inline sample data for frontend development
  summary.value = FALLBACK_SUMMARY
}
```

生产环境中 API 异常时，用户看到的是虚假模拟数据且无任何错误提示，极易造成错误决策。

**建议**：移除所有 mock 回退逻辑，或仅在 `import.meta.env.DEV` 条件下使用。

## 三、🟡 中风险问题

### 3.1 N+1 查询

| 位置 | 问题 |
|------|------|
| [TemplateServiceImpl.delete()](xzcpc-xzg/template/src/main/java/com/xzcpc/template/service/impl/TemplateServiceImpl.java:101-113) | 每个分区一次 DELETE，20 个分区 = 20 条 SQL |
| [TemplateList.vue](admin/src/views/template/TemplateList.vue:796-841) | 每个分区一个 HTTP 请求获取物料 |
| [MpMaterialServiceImpl.sortMaterials()](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/service/impl/MpMaterialServiceImpl.java:162-173) | 循环内逐条 selectById + updateById |
| [StoreServiceImpl.upsertStores()](xzcpc-xzg/task/src/main/java/com/xzcpc/task/service/impl/StoreServiceImpl.java:104-126) | 逐条查存在 + 逐条 insert/update |

**建议**：使用批量操作（`updateBatchById`、`in` 查询、单条 SQL 的 CASE WHEN）。

### 3.2 `selectList(null)` 全表查询

| 位置 | 问题 |
|------|------|
| `MaterialServiceImpl.getAllCategories()` | `SELECT *` 全表后 Java stream 取 category |
| `EmployeeServiceImpl.dashboard()` | `selectList(null)` 全量加载所有员工 |
| `MpTaskServiceImpl.list()` | `templateMapper.selectList(null)` 每次请求全表查模板 |

**建议**：使用 `select(String... columns)` 只取需要的字段，或加 WHERE 条件限制范围。

### 3.3 手动 JSON 解析异常被静默吞没

[MpTaskServiceImpl.java:476-477](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/service/impl/MpTaskServiceImpl.java:476-477)：

```java
} catch (Exception e) {
    return List.of();  // 解析失败静默返回空，无日志
```

[MpZoneServiceImpl.java:354-364](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/service/impl/MpZoneServiceImpl.java:354-364)：

```java
} catch (Exception ignored) {
    return null;  // 无日志
```

业务数据解析失败时没有任何日志，问题无法排查，UI 表现空数据，用户困惑。

**建议**：至少记录 ERROR 级别日志，并向前端返回明确的错误信息。

### 3.4 Caffeine 本地缓存多实例不一致

[CacheConfig.java](xzcpc-xzg/common/src/main/java/com/xzcpc/common/config/CacheConfig.java:22-37) 使用本地 Caffeine 缓存 stores（25h TTL）、materials（5min）等。多实例部署时，一个实例写入后其他实例在 TTL 内看不到更新。

**建议**：如果未来多实例部署，考虑 Redis 集中缓存或缩短 TTL。

### 3.5 `DeadlineGuardAspect` 错误地将第一个 Integer 参数当作 taskId

[DeadlineGuardAspect.java](xzcpc-xzg/mp/src/main/java/com/xzcpc/mp/interceptor/DeadlineGuardAspect.java:56-66)：

```java
for (Object arg : args) {
    if (arg instanceof Integer) {
        Integer taskId = (Integer) arg;  // 可能是 pageNum、sortNo 等
```

非任务相关接口若恰好有 Integer 参数，会浪费一次数据库查询。虽因查不到 task 而不会误报错，但逻辑不正确。

**建议**：改为检查参数上的自定义注解（如 `@TaskId`），或限定切面仅拦截特定 Controller 包。

### 3.6 `TaskServiceImpl.batchCreate()` 未校验重复任务

同一门店同一月份被重复调用会创建多个任务。无防重机制。

**建议**：创建前检查该门店该月份是否已有未提交的任务。

### 3.7 前端 401 处理潜在递归

[admin/src/api/index.ts](admin/src/api/index.ts:38-51)：`handle401()` 中的 `devLogin()` 使用同一个 axios 实例，如果 devLogin 也返回 401 会导致无限递归。

**建议**：`devLogin()` 使用裸 `fetch()` 或独立的 axios 实例。

### 3.8 前端删除操作失败仍显示成功

[ExpenseTypeManagement.vue](admin/src/views/expense/ExpenseTypeManagement.vue:136-139)：

```typescript
try { await api.delete(...) } catch { /* 吞错 */ }
items.value = items.value.filter(...)  // 无论成败都删
message.success('已删除')
```

API 调用失败时用户仍看到"已删除"提示，刷新后数据恢复。

**建议**：catch 中设置错误提示并 `return`，不执行后续删除逻辑。

### 3.9 前端 miniapp checkLogin 未 await fetchMe

[user.ts](miniapp/src/store/user.ts:56-75)：`checkLogin()` 调用 `fetchMe()` 未 await，token 校验在后台异步运行，UI 可能短暂显示错误数据再跳转登录。

**建议**：`await fetchMe()` 或使用 `Promise.then()` 确保状态同步。

### 3.10 前端 localStorage 存 JWT 易受 XSS

Admin 和 miniapp 两端均将 JWT 存在 localStorage，任何 XSS 漏洞可直接窃取 token。

**建议**：长期考虑 httpOnly cookie；短期确保对用户输入严格转义。

## 四、🟢 低风险问题

### 4.1 `TemplateList.vue` 超长单文件组件（2057 行）

**建议**：拆分为独立组件（分区面板、物料列表、拖拽逻辑等）。

### 4.2 `zone-entry/index.vue` 超长单文件组件（1165 行）

**建议**：提取语音识别、数值键盘等为组合式函数。

### 4.3 语音识别代码在多页面间重复

`detail/index.vue` 和 `zone-entry/index.vue` 中各有 ~70 行相同的语音识别逻辑。

**建议**：提取为 `useVoiceInput()` composable。

### 4.4 业务错误码硬编码为魔法数字

`4031`、`4032`、`4033`、`4040`、`401` 等错误码在多处直接写数字。

**建议**：定义 `ErrorCode` 常量类。

### 4.5 `MaterialManagement.vue` 用 `pageSize: 9999` 拉取全量物料

**建议**：后端支持分页，前端使用正常的分页尺寸。

### 4.6 `scan/index.vue` 中 `throw null`

```typescript
catch { uni.showToast({ title: '保存失败' }); throw null }
```

**建议**：改为 `throw new Error('保存失败')`。

### 4.7 缺少安全响应头

项目未设置 `X-Content-Type-Options`、`X-Frame-Options`、`Content-Security-Policy`、`Strict-Transport-Security` 等响应头。

**建议**：添加一个全局 Filter 设置安全头。

### 4.8 `Converter<String, Integer>` 空字符串报错

[WebConfig.java](xzcpc-xzg/common/src/main/java/com/xzcpc/common/config/WebConfig.java:25-31)：当前端传 `?id=`（空字符串）时，`Integer.valueOf("")` 抛异常（被 GlobalExceptionHandler 兜底为 500）。

**建议**：增加 `if (source == null || source.isEmpty()) return null;`
