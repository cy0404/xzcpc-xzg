## 状态映射（直接使用外部值）
PENDING_CONFIRMATION / IN_PROGRESS / PENDING_CONTACT / PENDING_ACCEPTANCE / CLOSED / OVERDUE
不再做 alias→内部值转换，直接用 task_platform 原始状态值。

### 回调逻辑（syncByCallback）
- 有 `title`/`issueNo`（完整回调）→ externalId 不存在则创建，存在则更新
- 只有 `status`（纯状态更新）→ externalId 不存在则跳过，不做任何操作
- 通过 chatId 反查 `store_info` 获取门店信息

### URL 前缀处理
- `prefixRelativeStr`：`/uploads/...` → 拼 baseUrl；`http://` → 替换为 HTTPS 域名
- 处理 records.photos（数组）、mediaUrls（字符串）、solutionPhotos（数组）
- covers replies.mediaUrls 中的所有嵌套字段

## 数据库优化
- `migration-material-add-name-index.sql` — material 表加 `(del_flag, material_name)` 联合索引
  - 慢SQL：`SELECT ... FROM material WHERE del_flag=0 ORDER BY material_name LIMIT 100` 从 ~670ms 降到 <50ms
- `schema.sql` 同步更新

## 报损后端（已有功能，无新增改动）
- 容器选择：`listContainers()` 按 id 升序（去皮→1号盆→2号盆→3号盆→4号盆）
- 问题处理：`overviewByStores()` 按门店返回 `PENDING_ACCEPTANCE` 计数供首页使用

## ExpenseDashboard 优化
- Controller 支持 `startDate`/`endDate` 参数（优先于 `range`）
- DTO `StoreRanking` 新增 `count`/`pctAmount`/`pctCount`
- Service `buildStoreRanking` 按门店统计金额+次数，双维度百分比；移除 `.limit(8)`
- 新增 `buildMonthlyTrend` 按月汇总支出金额
- `ExpenseDashboardResp` 新增 `MonthlyTrend` 内部类+`monthlyTrend` 字段
