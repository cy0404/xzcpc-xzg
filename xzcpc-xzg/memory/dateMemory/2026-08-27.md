## 关键设计（多轮纠错定稿）
- **匹配键**：接口 `id`（数字，如 171）↔ 本地 `store_info.store_code`（与企迈 code 同源）——⚠️ 用户明确纠正，不是接口其他字段
- **督导匹配**：接口 `supervisor.userId` ↔ `admin_permission.user_id`（飞书企业稳定 ID）；open_id 是应用维度不可用
- **新店建店**：store_id **本地自定义生成**（`cm` + 24 位小写字母数字，genStoreId 查重）——⚠️ NOT NULL 无默认值，取接口 id 会 500（1364 类）
- **upsertAccess 无条件覆盖**：按 (open_id, store_id) 匹配，存在则更新，source 一律置 `auto`——用户确认 196 行 manual 是初始化数据（非手工维护），可覆盖
- **督导名写本地名**：`admin_permission.name`（用户选「保持本地名」）；接口 displayName 只进 `nameMismatches` 提醒（如「李婉晴【实习营辅】13678726934」≠「李婉晴」）
- **xinfo 字段**：xinfo_store_name / province / city / district / address，无论有无督导都更新（新店建表时写入）；**旧店不改 store_name**
- **失效 auto 行不自动删**，进 `staleAutoRows` 报告人工确认
- 报告字段：totalStores / interfaceSupervisors / matchedSupervisors / matchedStores / noSupervisor / unmatchedByCode / newStores / newStoreIds / unmatchedSupervisors / nameMismatches / staleAutoRows

## 坑与排查
1. **mvn spring-boot:run -pl server 不带 `-am` 会崩**：依赖模块解析 **m2 仓库旧 jar**（template-1.0.0.jar 内含已废弃 `${material.api.url}`）→ `Could not resolve placeholder`。**必须 `-am` 用工作区源码**。详见 patterns P011
2. **生产 4026 jar 是 8 月 20 日旧包**：无 SupervisorSyncController（POST trigger → 404）；生产库 170 auto 行数据是**从测试库导入**的（store_id 与测试库验证时完全一致——随机生成不可能巧合，说明数据同源复制）；静态资源 Last-Modified 8-20 可佐证
3. **admin_permission.name 历史脏数据**：一半以上是企迈格式（带手机号/岗位/门店名，如「蔡苗苗 南亚 17633851863」「权志富17616598927（墨江 百树广场店）」）；本次只清理 2 位督导（马迎峰/唐敏），**改 name 不影响权限**（权限判断只用 open_id + roles，name 仅 JWT payload/展示/日志）
4. 1364 错误：测试库 store_id NOT NULL 无默认值，INSERT 缺该字段报错 → 逐行 UPDATE
5. 名字 mismatch 只有李婉晴 1 人 17 条（接口名带【实习营辅】+手机号），已确认不改
