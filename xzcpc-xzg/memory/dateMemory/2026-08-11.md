# 2026-08-11 牛油果泥单位换算修复 + 自动收货

## 牛油果泥单位换算修复

### 问题
原有换算逻辑无条件将所有牛油果泥数量 ×24、单位改为"包"。但实际情况中部分记录已用"包"作为单位，导致重复换算。

### 修复
`FeishuMessageService.java` 中 `convertAvocadoQty(materialId, qty, unit)` 和 `convertAvocadoUnit(materialId, unit)` 增加单位参数判断：
- `input_unit = "件"` → 数量 ×24，单位改为 "包"
- `input_unit = "包"` → 保持不变
- 非牛油果泥 → 原值返回

### 影响范围
- `FeishuMessageService.java` — 方法签名变更（qty 方法增加 unit 参数）
- `LossReportH5Controller.java` — 6 处调用全部更新：dailySummary、downloadVideosExcel（汇总+明细）、exportAvocado（汇总+明细）、downloadVideos（汇总+单文件命名）
- `LossReportDailySummaryJob.java` — 无需修改（未直接调用换算方法）
- H5 牛油果泥统计表（`avocadoStats`）新增 Java 层换算：统计表按 store_name 聚合后，对"件"的记录 ×24 并合并到"包"

### 编译验证
`mvn compile -q` 通过。

## 补发自动收货

### 新增 `LossReportAutoReceiveJob`
- 路径：`server/src/main/java/com/xzcpc/job/LossReportAutoReceiveJob.java`
- cron：每天凌晨 3 点
- 逻辑：查找 `status='confirmed_resend'` 且 `confirmed_at <= NOW() - 4天` 的报损记录 → 更新 `status='received'` + 写入 log（`action='auto_receive'`）
- 不会影响门店主动标记的 `not_received`（只处理 `confirmed_resend` 状态）

## 门店操作预警通知（WeeklyStoreWarningJob）

### 需求
每周一早8点，将上周无支出且无报损的门店发给督导和督导群。

### 实现
- **文件**：`server/.../job/WeeklyStoreWarningJob.java`
- **手动触发**：`POST /api/public/loss-report/trigger-weekly-warning`（在 `LossReportH5Controller` 中）
- **定时**：`@Scheduled(cron = "0 0 8 ? * MON")`，当前**已注释关闭**，等通知再开

### 逻辑
```
上周范围（周一~周日）
  → 查 expense_record（有支出的门店）
  → 查 loss_report（有报损的门店，不限状态）
  → 预警门店 = 活跃门店 - (有支出 ∪ 有报损)
  → 按 store_info.supervisor_name 分组
  → 飞书卡片发给督导个人（仅自己门店）+ 督导群（全部）
```

### 依赖
- `FeishuMessageService` — token、cardHeader("orange")、mdEl、sendToUser、sendToChat
- `supervisor_store_access` — 督导名→飞书 open_id 映射
- `sys_config.feishu_supervisor_group_chat_id` — 督导群 chat_id

### 督导-门店映射同步
- CSV（`_督导_门店_区域映射.csv`）→ `store_info.supervisor_name`（166 UPDATE）
- `supervisor_store_access` 从 `store_info JOIN admin_permission` 重建
- 工具脚本：`tools/compare_supervisor_csv.py` → `database/compare_result.sql`
- `admin_permission.name` 清除了备注后缀（如"实习督导"），与 `store_info.supervisor_name` 纯名字对齐
