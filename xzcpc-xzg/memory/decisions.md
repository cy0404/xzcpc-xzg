# 重要决策记录

## D001 — 快照隔离机制

- **日期**：2025-06
- **背景**：模板频繁调整（增删分区、更换物料），但已下发任务不能受影响
- **决策**：创建任务时完整复制模板 zone + zone_material 到 task_zone / task_zone_material
- **原因**：模板与任务彻底解耦，各自独立演进
- **放弃方案**：外键关联 + 版本号（模板删除分区会导致任务数据丢失）

## D002 — Maven 多模块而非微服务

- **日期**：2025-06
- **背景**：总部端和小程序端是两个独立部署单元
- **决策**：Maven 多模块单体，server 和 mp-server 两个 starter 共享业务模块
- **原因**：团队小、业务逻辑高度重合、部署简单
- **放弃方案**：微服务拆分（过度设计，运维成本高）

## D003 — 多单位换算引擎

- **日期**：2025-06
- **背景**：餐饮行业物料有多级包装（箱→件→瓶）+ 称重（kg→g→瓶）
- **决策**：`material_conversion_rule` 表，type 区分 unit/weight，sort_no 串联换算链
- **原因**：配置驱动，灵活扩展
- **放弃方案**：硬编码每种物料的换算逻辑（不可维护）

## D004 — 微信小程序独立 fat jar

- **日期**：2025-06
- **背景**：小程序端需要独立部署吗？
- **决策**：mp-server 独立启动器，端口 30261，context-path `/storeInventory`
- **原因**：两端流量特征不同，可独立扩缩容
- **放弃方案**：合并到 server 用路径区分（耦合太紧）

## D005 — 前端构建产物嵌入 fat jar

- **日期**：2025-06
- **背景**：Vue 3 前端如何部署？
- **决策**：Vite 构建到 `server/src/main/resources/static/`，Spring Boot 直接 serve
- **原因**：不需要额外 Nginx 配置，一个 jar 搞定
- **放弃方案**：Nginx 分离部署（增加运维复杂度）

## D006 — 飞书 OAuth + 多角色权限

- **日期**：2025-06
- **背景**：总部端需要登录 + 不同管理员看不同模块
- **决策**：飞书 OAuth → JWT → `admin_permission.role` 逗号多角色 → 路由守卫 + 拦截器
- **原因**：利用企业已有飞书体系
- **放弃方案**：自建账号系统（重复造轮子）
