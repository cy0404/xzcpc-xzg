# 智能订货拆单方案（每周一盘 × 双订货日分批发货）

**版本**：v0.2（评审稿）→ v0.3（后端已实施，2026-09-09）
**日期**：2026-09-08
**状态**：后端实施完成（改动 A~H），SQL 待执行，H5/小程序展示待改
**背景**：一次订一周的货仓库放不下。业务确认改为：**每周只盘点一次（数剩余数量），订货按订货日拆成两批（3 天量 + 4 天量）自动生成推店长确认**。

---

## 1. 业务规则确认（2026-09-08 用户拍板）

| # | 决策 | 内容 |
|---|------|------|
| 1 | 盘点频率 | **每周一次**：只数剩余数量（各店盘点日按现有订货周期，部分门店订货当天盘点——盘点任务保持现逻辑：订货日前一天 9:00 生成 ~ 订货日 5:00 截止，店在窗口内完成即可） |
| 2 | 订货时机 | **当天盘点当天订**：第一单 = 周盘提交即触发（现有逻辑已支持，盘点日差异不影响） |
| 3 | 订货拆分 | 每周 **2 批**：第二订货日 = `order_days` **第二值**（试点 '3,7' → 周日；**按各店实际订货周期拆**），单值店无第二值才推导 +4；覆盖天数按两订货日**实际间隔**切分（gap / 7−gap，不写死 4+3：'3,7' → 批1 4 天+批2 3 天；若某店 '1,4' → 批1 3 天+批2 4 天）；盘点任务只按首值生成一次（一周一盘） |
| 4 | 第二单库存 | **无实盘**：用"上次盘点 + 期间已到货 − 预估消耗"估算，明细标注"库存为估算值（基于 X 月 X 日盘点）" |
| 5 | 第二单生成 | **第二个订货日早上 9:00 自动生成**并推送店长确认（ORDER_CONFIRM 通知链路） |
| 6 | 安全库存 | **safetyDays = 1**（sys_config 调整，配送快 + 补货间隔短） |
| 7 | 周末 | **不单独建模**：订货日切法保证每个子窗口恰好含 1 个周末日，日均自动吸收（见 §3.2） |
| 8 | 试点范围 | **南亚 / 呈贡 / 新亚洲 / 测试门店 4 家** |

## 2. 验证结论（2026-08-31 ~ 09-08 只读回测）

### 2.1 拆窗预测精度（8 月逐日 PG 数据，滚动前 3 窗学习）

| 序列 | 中位偏差 |
|------|----------|
| 全直营合计（周三/周日拆窗） | 7.9% |
| 南亚店 店级合计 | 2.1% |
| 南亚店 冰勃朗 | 3.3% |
| 单店小量料（窗口 2~5 件）尾部 | 40%（量小随机波动，safety 兜） |

**结论**：3~4 天子窗口预测中位 2~8%，远好于整月预测（31%）——窗口越短越准，拆单不增加误差风险。

### 2.2 周末效应（8 月全店 + 单店）

| 维度 | 周末/平日 |
|------|-----------|
| 全店合计（被各店错峰抹平） | 1.10 |
| **单店主力料（南亚 冰勃朗/牛油果泥）** | **1.30~1.32** |
| 单日峰值（周五最高） | 1.40×（602 vs 平日 429） |

**关键**：订货按店算，单店周末高 ~30%；但**周三+周日切法下每个子窗口恰好含 1 个周末日**，历史日均（同型窗口）自动吸收周末水平 → A 法（单一日均）与 B 法（周末分开）回测打平（南亚店 A=2.1% 甚至更优）→ **不为周末加代码**。若未来切法产生"含 2 周末 / 含 0 周末"失衡窗口，再启用周末系数。

### 2.3 周末峰值判断

- 每周五~周日高位是**稳定星期模式**（4 个完整周同构），非随机
- 峰值日（活动/事件）不可预测 → 由 safety + 店长确认兜
- 订货日选周三：货周五到 → **库存最满时迎峰值**，切法合理

## 3. 方案设计

### 3.1 时间模型（以 原订货日周三（order_days=3）为例 → 第二订货日 = 3+4 = 周日）

```
盘点窗口 周二 9:00 生成任务 ~ 周三 5:00 截止（部分店订货当天盘点：窗口内任一时点完成）
周三     订货单①自动生成（提交即触发）：覆盖 周三~周六 4 天销售
         库存基准 = 实盘数（权威）
周五     订单①到货（配送 2 天）→ 库存最满迎周五六峰值
周日 9:00 订货单②自动生成：覆盖 周日~下周二 3 天销售
         库存基准 = 估算：盘点数 + 期间到货(真实) − 日均×天数(预估)
下周二   订单②到货；再次进入盘点窗口 → 周期闭环
```

> 第二订货日推导：`orderDay2 = (orderDay + 3) % 7 + 1`（原 3 → 7；原 4 → 1；原 5 → 2…），首批覆盖 4 天、次批覆盖 3 天。`order_days` 表字段不改（保持单值），由订货模块推导，避免 autoGenerateWeekly 误生成第二个盘点任务。

### 3.2 订货量公式（改动最小）

```
每单订单量 = 日均 × (覆盖天数 + safety 1) − 当前库存 − 在途
覆盖天数    = 本订货日 → 下一订货日前的销售天数（3 或 4，随订货日浮动）
当前库存    = 第一单：实盘；第二单：估算（盘点 + 到货 − 预估消耗）
```

| 单 | 覆盖 | 需求窗口 | 扣库存后进货 | 货架峰值 |
|---|---|---|---|---|
| ① 周三 | 4 天 | 4+1=5 天 | ~4 天量 | ~4 天量 |
| ② 周日 | 3 天 | 3+1=4 天 | ~3 天量 | ~3 天量 |

每周总进货 ≈ 日均×7（safety 不累积——每单扣当前库存，库存里含上次 safety 余量）。货架任何时候最多 3~4 天量，解决仓库容量问题。

### 3.3 预测源（沿用 2026-09 三源融合链）

- 主源：库存差日均（盘点+到货倒推），拆单后盘点间隔变短（约 7 天），日均更新更勤、更准
- 互证：店长订货节奏（偏差 ≤30% 取均值）
- PG：失真期不参与（`smart_order_use_pg=0`），企迈修复验收后切回
- 第二单的"预估消耗日均" = 同源库存差日均（即预测本身，误差中位 2~8%）

### 3.4 第二单库存估算误差保护

| 实际消耗 | 估算库存 | 第二单结果 |
|---|---|---|
| 比预估快（周末爆单） | 偏低 | 订多 → 安全 |
| 比预估慢 | 偏高 | 订少 → 但架上货多，平衡 |

误差方向自我纠正 + 下周二实盘拉回 + safety 1 天，三层保护。

**实施要点记录（2026-09-09）**
- 生成入口：批1 = 周盘提交补触发（`generateByWeeklyTask`）+ 3:00 job（原逻辑）；批2 = 第二订货日 9:00 job，与批1 共用"本周周盘已提交"前置（盘点周二晚 → 周日批2 时已提交 ✓）
- 切法（v0.2 修订）：批2 订货日 = order_days 第二值，覆盖 = 两订货日实际间隔（`coverageDaysOf`）；单值店回退推导 +4 → 4/3
- 幂等：同店同周盘任务同 order_day 只一张（DB uk_store_week_batch + 代码 count 双保险）
- 批2 估算口径（基础单位）：`估算 = 盘点数 + (盘点提交时刻, 现在] 内 PG 已送达订货 − dailyUse×已过天数`，下限 0（负估算不顶过整窗需求）；dailyUse 与批1 同源（库存差/订货节奏融合，周内无新盘点 → 预测不变）
- 误差保护：PG 同步延迟漏到货 → 估算偏低 → 批2 订多 → 安全方向
