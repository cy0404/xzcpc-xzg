# 智能订货数据源修复方案（企迈 PG 失真期过渡 + 回切验收）

**版本**：v0.3（已实施，待灰度验证）
**日期**：2026-09-07
**状态**：代码已提交（`6788938` 失真期改造 + `f608e75` 三源融合），待灰度验证后回切 PG
**背景**：2026-08-31 至 09-07 全量只读验证确认：企迈 PG 销量数据（`dwd.store_item_sales`）**系统性失真**；且确认**店长订货靠经验感觉**（贴合真实消耗 12.9%，优于 PG 建议）。方案定位：**库存差法（盘点+到货倒推）为客观预测主源，店长订货节奏与 PG 销量按互证规则融合**；**企迈侧修复后按本方案验收标准切回 PG**。

**系统价值定位（2026-09-07 业务确认）**：店长感觉目前比 PG 系统准（误差 ~13% vs ~30%+）。智能订货不替代感觉准的老店长，而是服务**没感觉的场景**——新店长、调店、新品期、活动期；同时为所有店提供**客观基线对照**（系统建议 vs 店长计划，偏差大时人工确认）。

**实施状态**：改动 A~F 全部落地，三源融合（v0.3 第 3.1 节）已提交，待部署 + 灰度 2 周验证。

## 1. 验证结论摘要（数据支撑）

### 1.1 PG 销量数据现状（13 家直营 8/31 月盘 + PG 原始数据）

| # | 发现 | 证据 |
|---|------|------|
| 1 | **51% 物料行 PG 无消耗记录** | 1418 行中 731 行 consumption=0（半成品 189、包装 46 等） |
| 2 | 有记录的行 **76% 低估、24% 高估** | 687 行：低估 523 / 高估 164 |
| 3 | 主力原料（冰勃朗/牛油果泥/糖浆等）**每店稳定缺 30~40%** | 订货≈真实消耗（店长按需订货且已送达），PG 销量只有真实 60~70%；万宏冰勃朗仅 43% |
| 4 | **7 月整体失真**（配比错，0.4/天 vs 6/8 月 1.9/天） | 6/1 行=6 月汇总、7/1 行=7/1~23 汇总、7/24 起逐日、8 月起才准 |
| 5 | 同物料跨店**方向不一致占多数**（46/75） | 不像配方级错误，像门店×渠道漏同步 |
| 6 | 部分物料**几乎全缺**（无纺布袋 0.1%、鲜果 10~30%） | 附赠品/自购品不走销量表 |
| 7 | 南屏街例外（109.9%，偏高估） | 需单独核对该店数据源 |

### 1.2 库存差口径回测（10 家直营，7 月日均 → 预测 8 月，盘点倒推验证）

| 口径 | ≤30% | 中位误差 |
|------|------|----------|
| **库存差日均**（579 样本） | **47%** | **31.2%** |
| 库存差日均（主力料冰勃朗 10 店） | **80%** | **16.8%** |
| 趋势修正（×7月/6月环比） | 40%（更差） | 37.4% |
| PG 销量日均 | 5% | ~79%（7 月脏数据无法回测） |

**结论**：库存差口径主力料中位误差 17%、全体 ~31%；趋势外推因单月环比噪声大而更差，不做。低估方向（65%）由快速补货（配送 2 天）自然兜住，**safetyDays 维持 2**。

### 1.3 订货量验证（店长"感觉"对照，2026-09-07 补充）

| 验证 | 结果 |
|------|------|
| 订货量 vs 真实消耗贴合度（515 样本） | ≤30%: **76%**，中位 **12.9%**（主力料 3~9%） |
| 7 月订货日均预测 8 月（中位误差） | 30.8%（与库存差 30.5% 几乎等价） |
| 订货>消耗（囤货倾向） | 59%（店长习惯性多订 ~13%） |
| 库存净变动 >50% 消耗的样本 | 仅 13%（多数店库存稳定） |

**结论**：店长"感觉"订货里含真实需求信息（贴合度优于 PG），但它是**人的主观判断**——新店长无感觉、旺季会错判、系统性多订。**订货数据只作"店长意图"参考与兜底，不作预测主源**（避免把人的偏差固化进系统）。

## 3. 短期改动方案（PG 修复前生效）

### 3.1 预测源融合链（核心，v0.3 已实施）

**目标**：三个口径**一起算**，按互证规则融合——库存差为客观主源，店长订货节奏与 PG 销量在"一致"时参与收窄、不一致时被丢弃：

```
每个物料同时算三个日均口径：
① inventoryDaily 库存差（上次盘点+期间企迈入库−本次盘点）÷天数   = 客观事实（含损耗/调货/自购）
② rhythmDaily    店长订货节奏（近90天已送达订货÷有货周数÷7）     = 店长实际需求（贴合真实消耗 12.9%）
③ pgDaily        PG 近4周日均（÷有数据天数）                    = 校验源

融合链（weekly/monthly 统一，2026-09 重构）：
① 有值 →
    与②偏差 ≤30% → dailyUse = (①+②)/2        mode=inventoryRhythm（两独立信源互证降噪）
    与②偏差 >30% → dailyUse = ①                mode=inventory（信盘点倒推；needs_review 橙标提示）
    use_pg=1 且 ③ 与当前日均偏差 ≤30% → dailyUse = (当前+③)/2   mode=blend（三源一致才收窄）
    use_pg=0（失真期）或 ③ 偏差 >30% → ③ 不参与数值
① 不可用 → use_pg=1 && 去年同周(×趋势) → use_pg=1 && ③ recent4w → ② orderRhythm → default 0.5
```

**"店长意图对照"（v0.2 起，已落地）**：生成建议单时每个物料同时算：
- 系统建议 = 融合日均 × 周期
- 店长近期单次订货 = 订货节奏日均 × 周期 ÷ factor（订货单位）
- 两者偏差 >30% → `needs_review=1` + reason 文案"您近期每次约订 X 件（差异较大，请核对确认）"；H5 明细行橙色 chip"⚠ 与您近期订货差异较大"
- 店长确认时以店长修改为准（感觉纠正系统）；店长未改即下单时以系统建议为准（系统兜住感觉）

**代码改动点（SmartOrderServiceImpl，已提交 6788938 + f608e75）**：

| # | 改动 | 说明 |
|---|------|------|
| A | blend 反转：不一致信库存差而非 PG | 验证证明 PG 系统性低估 30~40%，盘点误差 < PG 噪声 |
| B | `smart_order_use_pg` 开关（默认 0=失真期关闭） | 企迈修复后一个配置切回，不改代码 |
| C | pgSalesSum 汇总行防护（单日 ≥ 其余日均×20 剔除） | 防 6/1、7/1 整月汇总行被当单日爆 20~30 倍 |
| D | 停售检测护栏（近 90 天有已送达订货不判停售） | PG 漏记不误杀仍在补货的物料 |
| E | 回测 actual 改"窗口内已送达订货"为主口径（PG 仅兜底） | 否则回测不可信 |
| F | needs_review 店长意图对照（实体 + SQL + H5 橙标） | SQL：`database/migration-add-smart-order-needs-review.sql`（已执行） |
| G | 三源融合链重构（inventoryRhythm 模式 + 修正因子适配 + reason 文案） | 本版核心；修正：报损两源都吸收=0，调货/还货/自购×0.5 |

## 6. 风险与护栏

| 风险 | 缓解 |
|------|------|
| 库存差法依赖企迈报货接口拉取 | fetchInbound 失败已有降级（L505-509 捕获→inventoryDaily=null→落 orderRhythm/default），维持 |
| 盘点本身错误（店长录错） | diff 模块 is_large 复核 + adjusted_qty 修正后下次盘点即校正；blend 一致时取均值 |
| 上月盘点缺失（万宏型） | 改动 F 显式警告；周盘场景 prev=上周周盘不受月盘缺口影响（已确认周盘每周提交） |
| 新品/上新事件低估 | 不建模；配送 2 天 + 店长人工补单兜底（safetyDays=2 已定） |
| **店长感觉系统性多订 13%** | 订货量不作预测主源（只作参考对照），系统基线来自客观盘点 → 不把人的偏差固化 |
| **系统基线 vs 店长感觉冲突** | needs_review 偏差>30% 显式提示，店长确认时以店长为准（感觉纠正系统），未改则以系统为准 |
| orderRhythm 单位换算 | 订货表 unit→base 换算已验证（冰勃朗 1 件=12,000g 正确）；批量核对表见附录 |
