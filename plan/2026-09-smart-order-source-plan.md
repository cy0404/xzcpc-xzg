# 智能订货数据源修复方案（企迈 PG 失真期过渡 + 回切验收）

**版本**：v0.2（评审稿）
**日期**：2026-09-07
**状态**：待评审
**背景**：2026-08-31 至 09-07 全量只读验证确认：企迈 PG 销量数据（`dwd.store_item_sales`）**系统性失真**；且确认**店长订货靠经验感觉**（贴合真实消耗 12.9%，优于 PG 建议）。方案定位：**库存差法（盘点+到货倒推）为客观预测主源**，PG 销量与店长订货均只做校验参考；**企迈侧修复后按本方案验收标准切回 PG**。

**系统价值定位（2026-09-07 业务确认）**：店长感觉目前比 PG 系统准（误差 ~13% vs ~30%+）。智能订货不替代感觉准的老店长，而是服务**没感觉的场景**——新店长、调店、新品期、活动期；同时为所有店提供**客观基线对照**（系统建议 vs 店长计划，偏差大时人工确认）。

---

## 1. 验证结论摘要（数据支撑）

### 1.1 PG 销量数据现状（13 家直营 8/31 月盘 + PG 原始数据）

| # | 发现 | 证据 |
|---|------|------|
| 1 | **51% 物料行 PG 无消耗记录** | 1418 行中 731 行 consumption=0（半成品 189、包装 46 等） |
| 2 | 有记录的行 **76% 低估、24% 高估** | 687 行：低估 523 / 高估 164 |
| 3 | 主力原料（冰勃朗/牛油果泥/糖浆等）**每店稳定缺 30~40%** | 订货≈真实消耗（店长按需订货且已送达），PG 销量只有真实 60~70%；万宏冰勃朗仅 43% |
| 4 | **7 月整体失真**（配比错，0.4/天 vs 6/8 月 1.9/天） | 6/1 行=6 月汇总、7/1 行=7/1~23 汇总、7/24 起逐日、8 月起才准 |
| 5 | 同物料跨店**方向不一致占多数**（46/75） | 不像配方级错误，像门店×渠道漏同步 |
| 6 | 部分物料**几乎全缺**（无纺布袋 0.1%、鲜果 10~30%） | 附赠品/自购品不走销量表 |
| 7 | 南屏街例外（109.9%，偏高估） | 需单独核对该店数据源 |

### 1.2 库存差口径回测（10 家直营，7 月日均 → 预测 8 月，盘点倒推验证）

| 口径 | ≤30% | 中位误差 |
|------|------|----------|
| **库存差日均**（579 样本） | **47%** | **31.2%** |
| 库存差日均（主力料冰勃朗 10 店） | **80%** | **16.8%** |
| 趋势修正（×7月/6月环比） | 40%（更差） | 37.4% |
| PG 销量日均 | 5% | ~79%（7 月脏数据无法回测） |

**结论**：库存差口径主力料中位误差 17%、全体 ~31%；趋势外推因单月环比噪声大而更差，不做。低估方向（65%）由快速补货（配送 2 天）自然兜住，**safetyDays 维持 2**。

### 1.3 订货量验证（店长"感觉"对照，2026-09-07 补充）

| 验证 | 结果 |
|------|------|
| 订货量 vs 真实消耗贴合度（515 样本） | ≤30%: **76%**，中位 **12.9%**（主力料 3~9%） |
| 7 月订货日均预测 8 月（中位误差） | 30.8%（与库存差 30.5% 几乎等价） |
| 订货>消耗（囤货倾向） | 59%（店长习惯性多订 ~13%） |
| 库存净变动 >50% 消耗的样本 | 仅 13%（多数店库存稳定） |

**结论**：店长"感觉"订货里含真实需求信息（贴合度优于 PG），但它是**人的主观判断**——新店长无感觉、旺季会错判、系统性多订。**订货数据只作"店长意图"参考与兜底，不作预测主源**（避免把人的偏差固化进系统）。

## 3. 短期改动方案（PG 修复前生效）

### 3.1 预测源降级链调整（核心）

**目标**：库存差法（客观事实）为主源；PG 销量、店长订货均只做**校验参考**；切回开关留好。

```
调整后降级链（weekly 与 monthly 统一）：
① inventoryDiff（库存差日均）        ← 有 prev 盘点 + 企迈报货成功时必用（客观基线）
② orderRhythm（订货节奏日均）        ← 仅作①不可用（无盘点历史/新店/报货拉取失败）时的兜底
③ PG recent4w（近 4 周销量日均）     ← 仅当与①偏差 ≤30% 时用于 blend 互证（一致才信）
④ default 0.5                        ← 全无数据
```

**新增"店长意图对照"（本版核心）**：生成建议单时，对每个物料同时计算：
- 系统基线 = 库存差日均 × 周期
- 店长意图 = 近 4 周该店平均每次订货量（PG `purchase_order` 已送达，历史窗口 ≥2 次订货）
- 两者偏差 >30% 时，明细行标记 `needs_review`，前端提示"系统建议 X，您上几周订 Y，差异较大请确认"
- 店长确认时以店长修改为准（感觉纠正系统）；店长未改即下单时以系统基线为准（系统兜住感觉）

**代码改动点（SmartOrderServiceImpl）**：

| # | 位置 | 改动 | 说明 |
|---|------|------|------|
| A | L521-536 weekly 分支 | **blend 反转**：偏差 >30% 时信 **inventoryDaily**（改 useMode=inventory），不再信 PG | 验证证明 PG 系统性低估 30~40%，盘点误差 < PG 噪声 |
| B | L537-564 非 weekly 分支 | lastYear/recent4w 段加开关 `smart_order_use_pg`（sys_config，默认 `false`）；关闭时跳过 PG 段直接落 inventoryDaily | 企迈修复后一个开关切回，不改代码 |
| C | L488-490 等 PG 读取 | 加**汇总行防护**：窗口内单日值 ≥ 其余日均×20（月汇总行特征）→ 该行剔除、days 减 1 | 防 6/1、7/1 汇总行被当单日爆 20~30 倍 |
| D | L467-483 停售检测 | 近 7 天 PG 无销量**且**近 90 天订货节奏也无到货（orderRhythm 无记录）才判停售 | PG 漏记不误杀仍在补货的物料 |
| E | 回测 actual 口径 | backtest 窗口 actual 改为**库存差倒推**（prev 盘点 + 窗口内到货 − 期末盘点快照），弃用 PG 销量 | 否则回测不可信 |
| F | 生成明细 | 新增 orderRhythm 参考列 + `needs_review` 标记（偏差 >30%） | 店长意图对照，见上 |

### 3.2 差异模块边界修复（独立小改）

| # | 位置 | 改动 |
|---|------|------|
| F | `DifferenceCalcServiceImpl.findPrevSubmitTime` L560-571 | prev 提交与本次间隔 >45 天时（如万宏 7 月未提交→窗口 6/30~8/31）打 warn 日志并在 diff 结果标注"窗口跨 2 个月"，禁止静默回退 2 个月兜底 |

| # | 动作 | 说明 |
|---|------|------|
| G | 万宏 7 月任务补提交或标记 | 否则其 diff 窗口持续污染 |

## 5. 切回 PG 的验收标准（达标才切）

切回前跑一次全量对照（复用本方案回测脚本 `_backtest_inventory_diff2.py` 思路）：

| 指标 | 当前值 | 切回门槛 |
|------|--------|----------|
| 库存差 vs PG 近 4 周日均偏差 ≤30% 占比 | ~27%（579 样本含主力料） | **≥ 70%** |
| 主力料（冰勃朗等 TOP20）偏差 ≤30% 占比 | ~47% | **≥ 85%** |
| 覆盖率 <60% 物料占比 | 39/75 | **≤ 10%** |
| 切回后建议量与库存差建议量偏差 ≤20% 占比 | — | **≥ 80%**（灰度 3 店先跑 2 周） |

**灰度方案**：`smart_order_use_pg` 开关按门店维度扩展（`smart_order_pg_store_ids` 白名单）→ 先 3 家 → 2 周后对照 diff → 全量。

## 6. 风险与护栏

| 风险 | 缓解 |
|------|------|
| 库存差法依赖企迈报货接口拉取 | fetchInbound 失败已有降级（L505-509 捕获→inventoryDaily=null→落 orderRhythm/default），维持 |
| 盘点本身错误（店长录错） | diff 模块 is_large 复核 + adjusted_qty 修正后下次盘点即校正；blend 一致时取均值 |
| 上月盘点缺失（万宏型） | 改动 F 显式警告；周盘场景 prev=上周周盘不受月盘缺口影响（已确认周盘每周提交） |
| 新品/上新事件低估 | 不建模；配送 2 天 + 店长人工补单兜底（safetyDays=2 已定） |
| **店长感觉系统性多订 13%** | 订货量不作预测主源（只作参考对照），系统基线来自客观盘点 → 不把人的偏差固化 |
| **系统基线 vs 店长感觉冲突** | needs_review 偏差>30% 显式提示，店长确认时以店长为准（感觉纠正系统），未改则以系统为准 |
| orderRhythm 单位换算 | 订货表 unit→base 换算已验证（冰勃朗 1 件=12,000g 正确）；批量核对表见附录 |

## 7. 实施步骤（待评审后执行）

1. **代码改动 A~F**（SmartOrderServiceImpl + DifferenceCalcServiceImpl），约 1 个分支提交
2. 配置：`sys_config` 加 `smart_order_use_pg=false`
3. 回归：本机 18081 dev 实例跑 backtest（任务取 8/31 月盘、weekStart=9/7）确认 mode 分布变为 inventory 主导
4. 灰度：3 家直营店跑 2 周，对照建议单与实际到货/下次盘点；重点观察 needs_review 提示的偏差方向（确认是店长感觉偏多还是系统基线偏少）
5. 运营动作 G~J（万宏补盘、模板清理、南屏街核对、店长话术）
6. 企迈侧修复清单转交外部；修复后按第 5 节验收，达标切回 PG
