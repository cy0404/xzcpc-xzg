## 需求来源
- 设计稿：`projectDesign/Mini-program-end/smart-order.html`（URL 参数 `role=owner&scope=store&store=nanping&from=list`）
- PRD：`projectDesign/Mini-program-end/prd/智能订货.md`
- 用户拍板三决策：① 建议量算法先审阅（获批版见 xzcpc-xzg/memory）② **真实对接企迈下单** ③ 入口 = 工具页查看类 + 首页待处理事项，不做飞书提醒
- **页面形式（用户指令，晚于上三点）**：用 H5 页面 + web-view，参考入库管理（inbound-list/detail）；原生 uni-app 页方案被推翻删除

## 页面 = H5（xzcpc-xzg/upload/h5/ + static/h5 jar 副本）

### smart-order-list.html（列表页）
- URL 参数 `?token=&all=1&storeName=`（all=1 跨店视图；单店用 token 上下文门店）
- 概览面板（**不可点击**）：当前范围（全部门店/storeName）+「N 张待确认」chip（all 取 overview-total，单店取 overview 的 pending+submitFailed）
- 卡片：all 模式 `门店名 · 2026 年第 34 周建议订货单` + 绿色门店 chip；单店模式 `2026 年第 34 周建议订货单` + 状态 chip（pending 待确认橙 / syncing 同步中橙 / success 同步成功绿 / submit_failed 提交失败红）
- 副标题 `建议订货 ¥xx · N 个 SKU`；操作行 去确认›（pending）/ 重新确认›（submit_failed）/ 查看详情›（其他）
- `weekLabelOf()`：`2026-W34` → `2026 年第 34 周`（正则 `^(\d+)-W(\d+)$`）
- 相对链接跳 `smart-order-detail.html?id=..&token=..`；pageshow 返回刷新；下拉刷新（复用 inbound 阻尼 0.6× 模式，PULL_THRESHOLD=50）

### smart-order-detail.html（明细页）
- 顶部 sticky 返回头：`history.length>1 ? history.back() : 回列表`（web-view 内导航返回列表；navbar 返回键会整个退出 web-view）
- 周概览面板：绿色周标签 + 「建议订货单」+ 3 指标（建议品项 / 建议数量**实时联动步进器** / 状态带色）
- 状态卡 4 态：
  - pending 橙 ⏳「订货单待确认」/ `请确认每个品项数量，HH:mm 前提交企迈订货。`（deadline 提取 HH:mm，缺省 18:00）/ 生成时间
  - syncing 橙 🔄「正在同步企迈」/ 已保留清单文案 / 提交时间
  - success 绿 ✅「已生成企迈订货单」+ 企迈单号；**全 0 确认时后端不调企迈** → 「确认完成·已跳过企迈下单」
  - submit_failed 红 ⚠️「提交失败」/ submitError / 提交时间·已尝试 N 次
- 明细表：表头「物料 | 建议订货量」；行 = 物料名+规格+reason 灰字 +「可支撑 X 天」「单价 ¥x」chip
- **手写步进器**：qtyMap 本地状态（初始 confirmedQty ?? suggestQty，均 Number()||0）；[-]输入[+] + stock_unit；仅 pending/submit_failed 可编辑；锁定态只读显示数量；changeQty ±1 保留 2 位小数（称重换算有小数）；oninput 实时刷合计、onblur 归一化（NaN/负数 → 0）
- 底部固定栏：合计数量 + 「确认订货」（submit_failed 变「重新提交」）→ 自定义确认弹窗（「确认后将提交企迈生成订货单，数量可改为 0 表示本次不订。」）→ PUT /{id}/confirm **提交全部明细**（后端语义：未提交的明细视为 0 不订，全 0 直接 success 不调企迈）→ toast「已提交，等待企迈同步结果」→ load() 刷新；acting 防连点

### H5 通用约定（inbound 模式）
- `var API=window.location.origin+window.location.pathname.split('/upload/')[0]+'/api/mp'`
- token 走 URL 参数；`Authorization: Bearer`；信封 `{code,data,message}`：401 登录过期提示、非 200 toast message；showToast/confirm 弹窗；esc() 转义；内联 CSS 无外部依赖；两个页面 inline script 均 node --check 通过
- **部署**：线上位置 upload/h5/，改后传服务器无需打包；static/h5 是 jar 内副本

## 小程序侧改动

- 支持 `title` 参数：`uni.setNavigationBarTitle({ title: decodeURIComponent(q.title) })`；不传保持 pages.json 默认「入库管理」（inbound 等旧入口不受影响）

### 工具页（pages/tools/index/index.vue）
- 非员工 viewTools 首项「智能订货」卡片 `h5: true, url: ''`；模板点击 `t.h5 ? goSmartOrder() : goTool(t.url)`
- `buildSmartOrderUrl(all)`：`H5_BASE + '/upload/h5/smart-order-list.html?token=..'` +（all 时 `&all=1`，否则 `&storeName=..`）+ `&title=智能订货待确认`
- `goSmartOrder()`：all → 直接跳；单店 → **先 await switchStore(scope) 同步 token**（watch(scope) 之外再保险一次）再跳
- desc 动态 `每周建议订货单 · N 张待确认`（onShow 拉 fetchSmartOrderOverviewTotal，staff 门控不请求）

### 首页（pages/home/index/index.vue）
- PendingItem 加 `h5?: boolean`；all 模式按门店循环 🛒 条目 `h5: true`；单店模式 pending>0 单条 `h5: true`
- `buildSmartOrderUrl()`：切换门店后用最新 token 构建（`&storeName=` + title 参数）
- goPendingItem 末尾：`uni.navigateTo({ url: item.h5 ? buildSmartOrderUrl() : item.url })`
- 门控不变：数据请求按 `isManagerOrOwner`（request 层会 toast，员工调后端 403 会弹错）

## 踩坑记录
- **tools 页 onShow 里写 await 导致编译失败**：`Unexpected reserved word 'await'`（onShow 回调非 async）——抽成独立 async 函数 fire-and-forget
- **request 层会 toast 错误**：任何「某些角色不该调」的接口都要前端门控，不能靠后端 403 静默
- **web-view 导航语义**：H5 内部 location.href 跳详情 = web-view 内历史（detail 页 history.back 可回列表）；小程序 navbar 返回键会整个退出 web-view → 所以列表不设 H5 返回头、明细设
- **confirm 必须提交全部明细**：后端 `qtyMap.getOrDefault(id, 0)`，漏传 = 0 不订
- **编辑器缓冲区回写**：删除 qmaiWarehouseNo 后，Store.java/StoreInfo.java 曾被编辑器缓冲区恢复出该字段；最终已再删，全仓 grep 无残留
